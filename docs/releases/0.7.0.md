# Nowspace 0.7.0 — The inbox gets its inbox back

**Minor release with a schema bump: every instance sharing a vault must be on
0.7.0 before you move anything.** The bucket wire format is unchanged; the
bump exists so an installation too old to read the new setting refuses to
write rather than carrying on in the folder it knows.

### Added

- **Move Nowspace's files out of `0-Inbox`, from Settings.** Under *Obsidian
  Vault* there is now *Nowspace's files*: where they live, and a folder to move
  them to — anywhere in the vault, `0-Plan` by default.

  An inbox is defined by being emptiable, and these files never can be — they
  are the app's working state, not something you process and file. Half of what
  was in the folder could never leave it, which quietly cost you the one signal
  an inbox exists to give.

  The move takes **Nowspace's own file names only**. Anything else in the
  folder is yours and stays where it is.

- **The archive follows the plan folder.** `a0-Inbox` means "the archive of
  0-Inbox", and it stops being true the moment the plan leaves the inbox. The
  move takes the whole archive folder with it and renames it by the vault's own
  convention — `4-Archive/a0-Inbox` → `4-Archive/a0-Plan`, matching the
  `a1-Project` / `a2-Areas` already there. Every archived week stays readable
  from the week navigation; nothing is left pointing at a folder named after
  somewhere the plan no longer is.

  Re-running the move on a vault whose plan already moved does the archive
  alone, so a vault that got there first can be finished off.

- **The configuration file stays behind, with the tools.** It does not follow
  the plan files: it lives in `5-Meta/Nowspace/` (or `0-Inbox/`, where existing
  vaults have it), and that is precisely what lets the plan files go anywhere.
  A file cannot record its own location, so this one stays somewhere the app
  knows to look, and records where everything else went.

- **It is `Nowspace Configuration.md` now.** The file holds contexts, app mode,
  funnel limits, the diary folder and any extension's settings — almost nothing
  about Plan Week, which is the one thing the old name claimed. The old name is
  still read, forever: renaming happens only as part of an explicit move, and a
  vault that never takes that step keeps working.

### How the move behaves when something is wrong

Because it moves files in a synced vault, it refuses more readily than it acts:

- an unresolved `.sync-conflict-` copy in either folder — moving now is how
  the resolution gets lost
- a name that already exists at the destination
- a vault another installation has already upgraded past this one

And the ordering is the safety argument: **the files move first and the setting
is written last**, so a failure at any point leaves a vault pointing at files
that are still there. If the setting write fails after the files moved, they
are moved back and the error says so.

### Fixed

- **A long note could not be scrolled while you were editing it.** Every
  scroll on a phone fires `visualViewport`'s scroll event, and that event
  re-ran the caret chase — which scrolls **both** ways, up when the caret is
  below the visible band and down when it is above. So a note you had tapped
  into was pinned to the caret: scroll away and it snapped straight back, and
  the only way to reach further down was to drag the selection handle.
  Measured before and after on a 375px screen with a 10,000-character note:
  scrolled to 2000, one viewport-scroll event, and the old build came back to
  3. The box still re-fits itself on that event — a keyboard opening
  mid-scroll must not leave it hanging off the screen — but scrolling is you
  saying where you want to look, and nothing overrides that now.

- **The day's notes trapped you once you tapped into them.** Focusing the
  note pulls the page so the note's top meets the top of the page area —
  right, because that is what makes room for it. But every scroll on a phone
  fires `visualViewport`'s scroll event, and that re-ran the same
  positioning: scroll up towards the tasks and the next event pulled you
  straight back down to the note. Measured on a 375px screen: focus parks the
  page at 246, you scroll to 0, one scroll event returns it to 246. It stays
  where you put it now, and the panel is still re-fitted so a keyboard
  opening cannot leave the note hanging off the bottom.

  The same fault as the Notes tab's, by a different route — one chased the
  caret inside the note, this one repositioned the page around it.

- **Dark mode stopped at the edge of the note.** The markdown editor takes
  its palette from the nearest `data-color-mode` ancestor, and both editors
  pinned themselves to `light`; the boxes around them were `bg-white` and
  `border-gray-200` besides. A dark app had a white note in the middle of it.

  The theme now stamps `data-color-mode` on `<html>` alongside the `dark`
  class, so every editor follows it — including any added later — and the
  note card, its toolbar and breadcrumb, the day's notes box and the wiki-link
  autocomplete all take their colours from the theme's own variables. The
  diary already did, which is why it was the one window that looked right.


- **A copy parked beside the week file was read as a live week.** Anything
  named `Plan Week - ….md` was scanned as a current-or-future week, not just
  the dated ones — so a hand-made backup like `Plan Week - pre-dedupe
  backup.md` counted, and every `~r` line inside it read as a live instance of
  a repeat. The matching repeat then silently stopped spawning. Only
  `<name> - YYYY-wkNN.md` counts now.

### Upgrading

Update every instance first — desktop, phone, server. Then move, from any one
of them: the setting is in the vault, so the others follow on their next read.
An instance still on 0.6.x refuses to write once the vault is stamped, which
is the point of the bump; it will tell you to update rather than quietly
writing to the old folder.
