# Nowspace 0.8.1 — The time tracker opens on today, and files by sub-project

**Patch release. No format change.**

### Fixed

- **Opening Time comes back to today.** The tab never unmounts, so the date
  field and the period kept whatever they were last set to. Log something by
  hand on Friday, come back on Monday, and the field still offered Friday —
  a quiet way to file an entry on the wrong day.

  Opening the tab now sets the date to today and brings the period back to
  the current week or month.

  **Unless a timer is running**, in which case opening the tab does nothing
  at all: the row is the live editor then, showing the timer's own date, and
  glancing at a running timer should not move anything. A custom range is
  also left alone — it is a range you chose.

### Added

- **File an entry under a sub-project from the row.** A fourth icon, 🏷,
  beside the date, continue and delete ones, listing the sub-projects that
  entry's company already has. Pick one and the line becomes
  `Company/Sub: …`; pick *(no sub-project)* and it goes back.

  For the common case — one you meant to file and didn't — this is a press
  instead of retyping the line. Sub-projects are not configured anywhere and
  still aren't: one exists because an entry says `Company/Sub:`, so the
  picker offers what the period has actually seen. A brand-new sub-project
  is made the way it always was, by typing it in the description.

  The icon is absent on a line with no company, since there is no `/Sub`
  without one.

- **Push a start time back, without retyping it.** The Plan tab's running
  pill has had −5/−15/−30 for a while; Time has it now too.

  On a **running** entry the three buttons sit next to the start time, where
  it already is. On any **finished** entry it is a ⏪ beside the other row
  icons, offering −5/−15/−30/−60.

  The end is deliberately left where it is. The reason to reach for this is
  that the timer began after the work did — so the work ran longer than the
  entry says, and the duration should grow to match. It recalculates on its
  own, which is the part worth not retyping. A start never crosses midnight
  backwards: it stops at 00:00 rather than landing the evening before.
