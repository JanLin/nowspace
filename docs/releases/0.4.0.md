## Nowspace 0.4.0 — the funnel, the handoff, and a hard line on data safety

**⚠️ Update every installation.** 0.4.0 changes the bucket data format
(version 2) and adds a guard that refuses writes from out-of-date instances
— desktop apps, PWAs and self-hosted servers alike. An old instance can no
longer silently overwrite the new fields; it shows an update banner instead.
Update the server/backend first, then reload each app.

### The bucket funnel

Captured topics now move through explicit stages instead of all being
schedulable:

- **Captured** — the zero-friction inbox. Nothing is required, nothing is judged.
- **Binding** (max 4, configurable) — the small set of topics you're actively
  carrying, each held as a *question*. The fifth item forces a trade-off.
- **Ready** — bounded: at least one concrete next step and an s/m/l size.
  **Only Ready items can be scheduled** into the week.
- **Dormant** — parked on purpose with a wake date; silent until then.
- **Discarded** — dropped, with the reason recorded.

Around the stages:

- **Weekly review** (🧭 on the Bucket tab): a five-minute guided flow —
  reconcile slips, check each carried question, refill free Binding slots
  via two promotion tests, wake due dormant items, set one line for the week.
- **Slippage**: committing an item to a week that ends without it bumps a
  slip counter; three slips force the honest question — too big, or not
  actually important?
- **The Slate**: tap the Nowspace compass (top-left) for a read-only view of
  the questions you're carrying, plus a capture box. Solve questions show by
  day; after your evening cutoff only rehearse questions remain. No tab, no
  notifications, no scores — ever.
- **Diagnostics** (📊): time-in-stage, how items leave Binding, slip rate per
  group. Measures the system, never you.

### Agent handoff

Hand a Ready or Binding item to the agent bound to its area. Nowspace checks
that every attached note — including embeds and links — stays inside that
one area's folder, and refuses the handoff otherwise (no override). Agent
output lands back in your inbox as Captured, never as scheduled work.
Dispatch records live inside the area as plain markdown. Captured and
rehearse items can never be dispatched; at most three dispatches in flight.

### Data-safety guard (the reason to update everything now)

All three ways version skew can happen now fail loudly instead of corrupting:

- An out-of-date app writing through a newer server is refused with a clear
  "update or reload this instance" message, and shows an amber banner at boot.
- A newer app against an out-of-date server is refused by the existing
  field-strictness guard, with the same banner.
- A **format marker travels with the vault itself** (in the synced settings
  file), so even a fully self-contained installation — the desktop app,
  whose UI and bundled backend always agree with each other — detects that
  another device already writes a newer format, banners, and refuses to
  edit. The check re-runs every few minutes, so a Syncthing arrival is
  noticed mid-session.

From 0.4.0 onward, every future format change bumps one version number and
every stale instance immediately says so — whatever kind of instance it is.

### Fixes

- Desktop release builds work again (Tauri npm/crate version mismatch broke
  the 0.3.x installers — those releases contained only a source zip).
- Download links in the README now always point at the latest installers.
- Moving tasks between bucket and week no longer silently drops their steps.
- Note-link chips open notes created outside the app (fresh Obsidian notes,
  Syncthing arrivals) reliably.

### For self-hosted / always-on setups

Update the Mini (or any server) first, rebuild the desktop app's bundled
backend (`./build-backend.sh`), then reload each PWA — stale frontends show
the update banner until reloaded. A new backend pytest suite (42 tests) runs
in CI, including a canary harness that fails the build if any agent area's
content ever crosses into another.
