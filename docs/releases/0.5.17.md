# Nowspace 0.5.17 — What a task is, written next to the task

Patch release: **no data-format change**, bucket schema stays at **3**, so
this installs alongside any other 0.5.x instance sharing the vault.

### Changed

- **A task's facts now ride with its text.** Steps 🐘, a linked note 🔗,
  focus 🎺 and a pin 📌 sit straight after the task's name — the mirror of
  the waiting hourglass in front of it — at full strength, never a hover
  ghost. 0.5.11 put every icon behind one collapsing strip, which was right
  for the *offers* and wrong for the *facts*: on a phone, or in a day column
  of a multi-day view, a task with a note attached looked exactly like one
  without.

  What you can do to a task is unchanged and still lives in the strip or
  behind the ⋯ — including the 🔗 that adds a first link and the 🐘 that
  breaks a task down. Only the states that already apply move out. Both the
  Planning day rows and the Bucket.

### Fixed

- **A day note changed size the moment you tapped into it.** The rendered
  note was pinned to 12px inline while the textarea it swaps to is 14px, so
  reading and writing were two different sizes — and the inline value quietly
  beat the stylesheet rule that 0.5.16 set to match. Both are 14px on a 21px
  line now, from one place.

- **The line you were typing sat on the very bottom edge of a note.** The
  caret chase kept 8px under it — technically visible, and the first thing a
  phone keyboard's overlap eats. It keeps two lines of room now, in the Notes
  tab and in the day's notes.

- **Picking a search result could do nothing at all.** If the task lived in a
  context the tag lens had filtered out, or in a folded group the search
  hadn't named, the Bucket reset its stage filter and then quietly failed to
  find the row — no jump, no flash, no explanation. A search names one item,
  so the reveal now widens whatever is hiding it: tag lens to All, every group
  unfolded. The week view does the same.

  It also hunts for the row instead of taking two shots at fixed delays —
  widening the filters and refetching each re-render the list at their own
  pace, and the second shot regularly landed in the gap. The scroll to it is
  no longer "smooth" either: some engines drop a smooth scroll outright, which
  is a reveal that reveals nothing.

- **A comment was being displayed at the foot of the Bucket.** A block comment
  in JSX child position is text, not a comment; it had been rendering since
  0.5.11.
