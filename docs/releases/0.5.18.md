# Nowspace 0.5.18 — Tasks go where you put them

Patch release: **no data-format change**, bucket schema stays at **3**, so
this installs alongside any other 0.5.x instance sharing the vault.

### Changed

- **Ultra focus is offered before the timer, and no longer needs one.** The
  🎺 asked one question — 15 minutes or 30 — and the curtain that covers every
  other task was buried inside the running timer's panel. But what stops you
  settling is usually the rest of the list, not the absence of a clock, and
  being made to pick a length you didn't want to get the curtain is how you
  end up with neither.

  It now leads that prompt: **🕶 Ultra focus — cover the rest**, then *or give
  it a clock* with the two pomodoro lengths under it. Choosing the curtain
  starts no timer and runs until you lift it — a pill at the foot of the day
  does that, since without a timer there's no panel to hold the control. The
  timer's own ultra-focus button is unchanged for when you want both, and a
  curtain raised with a pomodoro still lifts when that pomodoro stops or its
  task is ticked off.

### Fixed

- **A dragged task landed a row short of where the indicator said — or didn't
  move at all.** The drop read its target from React state, and a real drag
  fires its last `dragover` and the `drop` back to back within one frame: the
  state that dragover set hasn't committed yet, so the drop still saw the
  previous position and put the task back roughly where it started. It was
  intermittent by nature — a slow drag with a pause before releasing worked
  fine, which is what made it look like the list was being stubborn.

  Dragging a *group* never had the fault, because a group drag carries its
  target in a ref rather than in state. That's exactly why groups moved and
  tasks didn't. The task drop reads a ref now too.

- **After a drop, the view follows the task.** Dragging to the bottom edge of
  a long list makes the browser scroll there on its own, and it stayed there —
  so moving a task back up left you looking at the end of the list with no
  sign of where the task went. Measured on a 40-task day: parked at the bottom
  (scroll 845), moving a task to near the top now brings the view with it
  (scroll 291, the row on screen). A row already in view moves nothing.

- **The ＋ on a group header added to a different section of the same group.**
  It searched the whole day for the last task carrying that group name and
  inserted after it. A group can have two runs in one day — dropping an
  ungrouped task into the middle of one splits it — and the ＋ at the top then
  fired the new task to the far end of the day, past every ungrouped task.
  What that looks like from the outside is everything below jumping above it.

  The ＋ now adds to the section it sits on, and a double-click on a row adds
  next to that row. Typing a "Group: task" into the day's own add row still
  joins the existing group rather than opening a second heading, which is what
  that rule was for.

- **The ⋯ menu covered the steps it had just opened.** It hangs under the row,
  which is precisely where a task's steps appear. Asking for the steps is
  asking to read them, so the menu closes when they open — and if you open the
  menu while they're already showing, it opens above the row instead.

- **A step's own icons were half the size of every other icon.** 10px against
  the row's 14px: the drag handle, the tick, promote and delete were there but
  not really visible. They match the task row now.

- **A step's promote and delete were unreachable on a touch screen.** They
  wait for a hover of their step, and a phone has no hover to give. They show
  faintly there instead, the same compromise the other row icons make.

- **The 📂 group list could not be dismissed.** Opened by mistake, it stayed:
  no Escape, no click-outside, so the only way past it was to pick a group and
  undo the move. Escape and a click outside both close it now — in the Plan
  and in the Bucket, which had the identical gap — along with the other row
  menus that already closed on a click but never on Escape.
