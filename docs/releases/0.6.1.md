# Nowspace 0.6.1 — What the first extension found

Patch release: **no data-format change**, bucket schema stays at **3**, and
`HOST_API` stays at **1** — adding a seam function or an argument is additive
by the rule in `backend/host.py` itself. With no extension installed, every
change here is invisible.

Four gaps, found by writing an extension against the 0.6.0 seams. That is
what the boundary is for: each one is a change to the baseline rather than a
reach through it.

### Fixed

- **An extension could not reach `registerSurface` at all.** The generated
  registration called `register()` with no arguments, and the baseline is not
  a published package — so there was no way to obtain the registry from
  outside the repository. The seam existed and was unreachable.

  The host is passed in now: `register(host)`, where `host` carries
  `registerSurface`, `registerWeekSource`, `surfaceEnabled`, `externalRef`
  and `HOST_UI_API`. An extension declares that type locally and imports
  nothing from the baseline, which is what lets it build with no alias, no
  `tsconfig` path mapping and no bundler `external` entry — and keeps React
  to the single copy the host loaded.

  An alias (`nowspace/surfaces`) was the alternative. It needs matching
  configuration in every extension, in two places, and behaves differently in
  dev and in a build. An argument needs none of that.

- **An extension router could not find the vault or its own settings.**
  `backend.host` gains `vault_root()` — for resolving a configured path
  against the vault this server is actually pointed at — and
  `addon_settings("<id>")`, the server-side mirror of the `addons` block
  clients already get. Both read-only: every write still goes through
  `vault_io`, where the guards live, and there is no setter because an
  extension editing baseline settings is a seam of its own rather than a hole
  in this one.

- **`npm run dev` skipped extension generation.** `build` ran it and `dev`
  did not, so an extension was present in a production build and absent in
  the one place it is actually being developed — where it looks like the
  registry is broken. `dev` runs it too now, and `tauri:dev` inherits that
  through `beforeDevCommand`.

### Changed

- **`docs/EXTENSIONS.md`** — the allow-list gains the two host functions; the
  surface example is one an extension can actually write; and two notes that
  would otherwise cost someone a day: Tailwind v4 does not scan built
  packages under `node_modules`, so classes in a prebuilt extension bundle
  produce no CSS (use inline styles with the baseline's CSS variables, which
  follow the theme), and an extension ships a **built** bundle with `react`
  external, since raw JSX resolved from outside the app's `node_modules`
  cannot find `react/jsx-runtime`.
