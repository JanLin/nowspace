# Nowspace 0.6.2 — Where the plan lives is the vault's decision

Patch release: **no data-format change**, bucket schema stays at **3**. Every
path resolves exactly where it did before — moving anything is a later,
deliberate step, and this release is what makes it possible.

### Added

- **`Plan Week README.md`, in the folder with the files it describes.** The
  plan is a handful of markdown files someone will eventually open in Obsidian
  without Nowspace running — you in a year, or anyone you share a vault with.
  Now the folder explains itself: a table of every file, what it is and how
  long it lives, how the bucket and the week relate, what happens at the turn
  of the week, and what is safe to edit by hand.

  It is generated from the paths this installation actually resolved, so it
  cannot drift from the truth, and it is rewritten only when it would differ —
  a file rewritten on every start is a file Syncthing ships on every start.

- **`plan.folder` and `plan.archive_folder` — vault settings.** Where the Plan
  Week files live, and where finished weeks are archived, as paths relative to
  the vault root:

  ```yaml
  plan:
    folder: 0-Inbox                     # default
    archive_folder: 4-Archive/a0-Inbox  # default
  ```

  Deliberately settings in the **vault**, not in each installation's
  `config.yaml`: two instances sharing one vault have to agree about where the
  plan is, and the only thing that legitimately differs between them is where
  the vault itself sits on disk.

  The defaults are exactly today's locations, and a vault with no `plan:`
  block resolves identically — the first test in `test_plan_folder_setting.py`
  is that acceptance, not a claim in a commit message.

- **The settings file is found rather than hardcoded.** `Plan Week
  Configuration.md` is looked for in a fixed order — `5-Meta/Nowspace/`, then
  `0-Inbox/` — so it can move out of the inbox with everything else. The order
  is compiled in and identical everywhere, which is what keeps it from being a
  per-device setting: a file cannot record its own location.

### Fixed

- **A week write no longer ignores a vault a newer installation has upgraded.**
  The skew guard refuses writes when the vault's format marker is ahead of the
  installation — but it only ran on *bucket* saves. Week saves went through
  unchecked, which was harmless while every instance agreed where the week file
  was, and stops being harmless the moment that becomes a setting: an
  installation too old to read `plan.folder` would carry on writing the folder
  it knows, leaving two live week files in two folders with Syncthing keeping
  both. Week saves check it now.

### Changed

- **The vault root is no longer re-derived from a folder name.** It was
  computed by matching the literal `0-Inbox`, in three places, which is what
  made the plan folder immovable: pointing it elsewhere silently redefined the
  vault root and took every `2-Areas` link, the vault browser and the archive
  with it. The root comes from configuration; the plan folder is its own
  setting.
