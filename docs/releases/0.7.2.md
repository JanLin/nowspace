# Nowspace 0.7.2 — The week rolls over while you are looking at it

**Patch release. No format change**, so 0.7.x instances share a vault happily.

### Fixed

- **"Archived week 2026-wk34 not found in 4-Archive/a0-Inbox."** Two faults in
  one sentence, both reported from a vault whose archive is
  `4-Archive/a0-Plan`.

  The folder in the message was **hardcoded**. Since 0.7.0 the archive follows
  the plan folder, so for anyone who moved their files the message named a
  directory the app had never looked in — and sent you to check a folder that
  in this vault does not exist. It now names the folder actually searched.

  And the week really was missing, for an honest reason: `Plan Week.md` was
  still holding it. A finished week moves to the archive when Nowspace reads
  the current week, and **an app left open across the rollover never re-reads
  it** — the freshness check compares the file's timestamp, and a calendar
  turning over changes no file. So the app went on showing last week as this
  week, and the week it offered to look *back* at was the one still sitting in
  `Plan Week.md`.

  Two changes, either of which is enough on its own:

  - The app now notices the calendar day changing under it and re-reads the
    current week — which is also what archives the finished one. Unsaved edits
    still get the usual banner rather than being reloaded from under you.
  - Looking back now runs the same transition first, so a stale client heals
    the rollover instead of reporting it as a missing file.

  Nothing about the archive itself was wrong: with the plan folder moved, weeks
  archive to `4-Archive/a0-Plan` exactly as configured.

### Notes

If you are looking at this with a week still stuck, open the Plan tab — one
read of the current week is all it takes.
