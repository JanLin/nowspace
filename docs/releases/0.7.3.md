# Nowspace 0.7.3 — A finished week will let you in, if you ask

**Patch release. No format change** — the bucket schema is untouched, so
0.7.x instances share a vault happily, and an instance that has not updated
simply refuses the new write instead of misreading it.

### Added

- **An edit override on past weeks.** A week in the archive still says
  *📁 Archive — read only*, and next to it there is now a quiet **edit**.
  Press it and the week behaves like any other: take a task out to the
  bucket, fix a line, add a `[[link]]` in the day notes.

  The archive was never sacred — it is your own notes, and going back to a
  finished week to move something out of it is ordinary work. What it should
  not be is something that happens by accident, so the override is one
  deliberate press, it is announced (*📝 Archive — editing*, with **done**
  next to it), and **it does not survive leaving the week**. Come back later
  and it is read-only again.

  The refusal underneath is unchanged for anything that does not ask: a save
  that does not carry the override is still turned away, which is what an
  instance running an older version sends. Nothing can write a past week
  while believing it is somewhere else.

  One thing worth knowing: saving a past week rewrites its day sections in
  Nowspace's own formatting, exactly as saving the current week does. If an
  old week has hand-written formatting in its task lines, editing it here
  will tidy it. The day notes are edited in place and are not affected.

### Notes

The bucket panel stays hidden on a past week — you can push a task out of a
finished week, not pull one into it.
