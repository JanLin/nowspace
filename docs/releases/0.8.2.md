# Nowspace 0.8.2 — Sub-groups on a task

**Patch release. The file grammar is unchanged** — see the note at the end.

### Added

- **A task can sit in a sub-group of its group.** The group heading is exactly
  what it always was; the task carries the sub-group itself:

  ```
  * Rotary:
      - [ ] /Inbounds: book the airport pickup
  ```

  The 🏷 picker now has two steps. The first is the group, as before, with
  **＋ new group…** added — the list only knows this week's groups, so one you
  used a month ago has to be typed. The second appears once the task has a
  group: the sub-groups that group already has, plus **＋ new sub-group…**.

  Nothing declares a sub-group. The first task to carry the prefix creates
  one, exactly as groups have always worked, and typing `/Inbounds: ` in front
  of a task is the same thing as using the picker. The chip keeps the slash so
  that stays obvious, and clicking a task to edit shows the raw label — prefix
  and all — so the notation is never silently lost.

  A sub only means something inside a group: on an ungrouped task the same
  text would read as a group *named* `/Inbounds`, so the second step appears
  only once there is a group to put it in.

### Notes

The file grammar did not change. A task under a group heading has always been
stored with its group re-attached and its own words after it, so
`/Inbounds: book the pickup` is simply those words — it already round-tripped
through the reader and the writer before this release knew what it meant. An
instance that has not updated shows the prefix as part of the task's text:
visible, never lost, never re-grouped. `bucket_schema` is untouched at 4.
