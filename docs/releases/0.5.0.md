# Nowspace 0.5.0 — Repeating work, one copy at a time

Minor release: the bucket schema moves from **2 to 3** (`recurrence_id` and
`due_date` on bucket items, riding the lines as colon-free `~r` / `~du`
tokens). As always with a schema bump, every installation sharing the vault
must upgrade together — older instances refuse to edit rather than silently
flatten the new fields.

The theme of the release is one distinction: **what a miss means.** If
missing it creates debt someone can collect — the bill, the chore, the
customer visit — it's a recurring *task*. If missing it only breaks a
pattern — practice, a ritual — it's a *habit*. Nowspace now has an honest
home for both.

### Added

- **Habit note links.** A habit can point at the note that explains how:
  `- tai chi: 2x/week, [[Tai Chi form]]` in Plan Week Habits.md, or the 📄
  field in the Habits editor. The link shows up wherever the habit does —
  on the strip and the Habits tab. Reference material only: the link must
  target a note, never a work-item file, and a habit gains no completion
  semantics, debt or due date from it. No more placeholder tasks that exist
  just to keep instructions findable.

- **Recurring task templates** (↻ Recurring on the Bucket tab). A template
  is defined once — title, size, when it comes back, optionally a first
  action, a group and a how-to note — and is *already bound*: creation
  passes the same gate as Shaping → Ready (size always; interval templates
  must also name their coordination step). Templates live in
  `Plan Week Recurring.md`, hand-editable like everything else.

  - **Calendar templates** (`monthly on 25`, `weekly on mon`) spawn one
    ordinary Ready copy on the date, carrying a quiet due date. **There is
    only ever one live copy**: if the previous copy is still open when the
    next date arrives, no second copy appears — the date moves forward and
    the miss is noted on the template. The overdue pile is unrepresentable,
    not discouraged. Spawning is sync-safe: two devices reaching the same
    date write byte-identical lines.

  - **Interval templates** (`every 6w`) are measured from the last actual
    completion — a slipped visit never drifts into calendar fiction. They
    never spawn on their own and never appear in Timing uninvited: when the
    interval has passed, the template surfaces in the weekly review, and
    accepting creates a task whose first action is to propose a date. The
    review is the reminder; nothing pings.

- **The template question.** Misses accrue on the template — never on you,
  and never visibly outside the review. At three consecutive misses the
  weekly review asks once: *wrong cadence, too big, or not a task at all?*
  The exits are adjust the schedule, scope it down, retire, or **demote to
  habit** — a migration that retires the template and creates a habit
  carrying the note link and a weekly target.

- Two new weekly-review steps carry all of this. Both are empty most weeks
  and cost zero seconds when empty — no "nothing to show" screens.

### Changed

- **Recurring copies are excluded from slip accounting.** A recurring copy
  committed to a week that closes incomplete no longer touches
  `slip_count` and never enters the 3-slip question — the miss routes to
  its template, where the question that actually has an answer lives. The
  slip-by-group diagnostics exclude them for the same reason.

- Week close credits recurring completions in the closing week file before
  archiving it, so a copy checked off late (or synced in unread) never
  reads as a miss.

### Format notes

- New tilde tokens `~r<6 hex>` (template id) and `~du<date>` (due date) are
  colon-free because, unlike the rest of the funnel family, they ride week
  lines too — the id must survive scheduling so completion credits the
  template. Old backends round-trip them as opaque text.
- The habit note token is a bare wikilink in the target segment; older
  backends ignore it on read (their Habits editor drops it on save, same
  as every habit field under skew).
- `Plan Week Recurring.md` blocks preserve unknown `- key: value` lines,
  so future fields round-trip through this version.
